## Design decisions for Part 27 (2026-11-12, advisor-checked)

- Every Part 27 REQUIREMENT section returns `s 903(1) status of a requirement` (complied with / not complied with / does not apply / not covered) via helper `s 903(1) the status of the requirement` (inputs: `excluded` MAYBE BOOLEAN from the excluding sections, `complied` BOOLEAN). Exclusion functions return MAYBE BOOLEAN (JUST TRUE = the requirement does not apply).
- s 903(1) aggregator: `s 903(1) the requirements of this Part do not bar the court` over a LIST of statuses (any not complied -> FALSE; any not covered -> NOTHING; else TRUE).
- "if the court is satisfied that the conditions have been complied with" (916, 917, 918, 931, 932, 934): the conditions are separate functions of facts; the exemption function takes the court's satisfaction as one more conjunct input (one fork line, F4).
- "one month before/after" = library `add months` (clamps day); "the period beginning one month before, and ending on, the date" = [one month before the date, the date], both ends inclusive (fork F6: counting a month).

## Pitfalls found (loud and silent)

- SILENT: `NOT (x) OR y` and `a AND NOT (b) AND c` read as `NOT ((x) OR y)` and `a AND NOT ((b) AND c)`. Found by two failing assertions; fixed by writing `((NOT (x)) OR y)`; grep of the templates for the pattern is clean now.
- `%%QUOTE` inert blocks must sit before a `§§` heading (or end of file): a quote run followed by another run in the same block merges with it and srcrefs reports an orphan.
- srcrefs strict: an aggregating function whose @ref spans several later REFs must come FIRST (its quote run covers the span); the narrower ones use %%LOC.
